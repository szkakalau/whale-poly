# SightWhale 后端管道深度分析报告

> 分析对象：`whale-poly/whale-monorepo`（Python 单仓库）。路径均为仓库相对路径。

## 1. 事件管道实现

### 1.1 五服务结构（每服务 = FastAPI api.py + Celery worker.py）

| 服务 | 端口 | API 职责 | Worker（Celery beat + Redis BLPOP） |
|------|------|---------|-----------------------------------|
| `services/trade_ingest` | 8010 | `POST /ingest/trade`（admin 鉴权）入队；blog/stats/history 读接口 | `ingest-markets` 120s、`ingest-trades` 30s、`consume-incoming-trades` 3s、`daily-spotlight` 20:00、`generate-daily-article` 20:05、`rebuild-smart-collections` 86400s、`ingest-smart-money-leaderboard` 43200s、`health-check` 3600s |
| `services/whale_engine` | 8011 | `/whales/{wallet}`、`/whales/leaderboard`、`/diag/score-system`、`/vw/*` | `consume-trade-created` 1s、`recompute-whale-stats` 300s、`compute-vw-metrics` 3600s、`prune-vw-snapshots` 86400s |
| `services/alert_engine` | 8012 | `/alerts`、`/alerts/recent`、`/alerts/force`、admin diag | `consume-whale-trade-created` 1s |
| `services/telegram_bot` | 8013 | bot 生命周期 + `/admin/diag/*` | `consume_alerts_forever`（BLPOP `alert_created`） |
| `services/payment` | 8014 | `/checkout`、`/webhook`、`/plans`、订阅管理 | 无队列消费者；lifespan 内跑 `_mark_expired_forever`（1h 一次） |

队列链（Redis List，BLPOP + LPOP 批量）：
```
Polymarket API → trade_ingest(ingest_trades) → "trade_created" → whale_engine
  → "whale_trade_created" → alert_engine → "alert_created" → telegram_bot → 订阅者
```
外加一条 `trade_ingest_incoming`（HTTP 注入路径，worker 用 Lua `_BATCH_LMOVE` 原子搬到 `:processing`，崩溃后可恢复）。

关键事务纪律：**DB commit 之后才 push 到 Redis**（`whale_engine/worker.py:60-87`、`alert_engine/engine.py:369-396`），避免孤儿队列消息。

### 1.2 services/unified — 单进程统一模式（当前生产形态）

- 单 FastAPI 进程替换 8 个微服务；`InMemoryRedis` 打补丁进 `shared.async_utils._redis`。
- 4 个 sub-API mount（`/whale`、`/alert`、`/payment`、catch-all `/` = trade_ingest）。
- 16 个 worker 全部改写为 asyncio 循环（`worker_loop.py`），带心跳上报 `/health`。
- 切换机制：`REDIS_URL` 空 → InMemoryRedis（统一模式）；非空 → 真 Redis（多服务/Celery 模式）。
- 生产入口 `docker/entrypoint-unified.sh`：`alembic upgrade head` 后 `uvicorn --workers 1`。
- `render.yaml` 注释：从 8 服务 + Redis（$127.37/月）降到 1 服务（$17.50/月）。

## 2. 鲸鱼评分系统（核心 IP，`services/whale_engine/engine.py`）

### 2.1 实时识别（`process_trade_id`）
- `detect_behavior`：spike（20m 内单笔 ≥$5000，置信 80）/ build（2h 内 ≥3 笔 buy 且 ≥$10000，置信 75）/ exit（sell ≥0.5×buy 且 ≥$5000，置信 85）。
- 准入：`score ≥ 85 且 usd ≥ 5000` 或 `score ≥ 70 且 usd ≥ 2500`；注意 `score = max(score, score_hint)` 把行为置信度直接混入质量分。
- 仓位核算 `_apply_trade_to_position`：多空平均价记账，action_type ∈ {entry, add, reduce, exit}，`SELECT … FOR UPDATE` 防并发。

### 2.2 周期评分 `recompute_whale_stats`（真正的评分引擎）
```
whale_score = (0.30·performance + 0.25·consistency + 0.20·timing
             + 0.15·risk + 0.10·impact) × age_mult × (0.2 if wash else 1)
```
- performance = 0.7·_score_roi(roi) + 0.3·(win_rate×100)；ROI ≤ −50%→0，≥ +50%→100。
- consistency = win_rate×100 − vol_penalty（stddev_pnl/(mean_abs_pnl+1)×15，上限 60）。
- timing = ((1−entry_percentile) + exit_percentile)/2×100。
- risk = 0.7·dd_score + 0.3·_score_rr；dd_score 以 max_drawdown/total_vol 计。
- impact = 0.5·log(avg_trade_size, 10000) + 0.5·liq_score（单笔占市场 24h 量比例）。
- 小样本（<5 笔）打折；age_mult = 1 − 0.3·e^(−age_days/3)（新钱包封顶 ~70 分）；wash 检测（单一市场集中 + PnL≈0）→ ×0.2。
- 多窗口合并：7d/30d/90d 权重 0.2/0.4/0.4（trades≥3 才参与，再归一化）。

### 2.3 钱包聚类
**没有真正的链上实体聚类**（无 proxy-wallet 关联、无同 owner 识别）。只有：地址归一、Polymarket 官方 top-50 榜灌入 WhaleProfile、用户自定义 collections/smart_collections 规则筛选。

### 2.4 校准
**没有反馈闭环校准**，只有监控：`/diag/score-system`（分桶分布）、`/stats/home`（分档已实现胜率/ROI）、`/history`（whale_trade_history.pnl + Gamma 结算价双算 ROI）。

## 3. 告警规则

- `should_alert`：score≥85 无条件；usd<100 拒；score<80 或 usd<3000 拒；score≥80 → high 否则 low。
- 冷却：same_wallet_same_market=600s、same_market_different_wallet=60s、increased_position=300s；旁路（usd≥2×last 或 elapsed≥300s 且 usd≥last）。
- 投递侧 v2 冷却：`effective_score = score + log10(notional)×5`，分档 60s~900s × plan 系数（FREE×2、ELITE×0.5），digest 缓冲合并。
- plan 分层：free（10m 延迟、3 条/天）、pro（0 延迟、min_score 70、follow 20）、elite（min_score 80、follow 100、high_confidence_first）。免费档延迟用 `asyncio.sleep` 实现。

## 4. 数据模型与迁移

- 28 张表：wallets/whale_scores/whale_stats/whale_profiles/whale_positions/whale_trade_history/trades_raw/whale_trades/markets/market_vw_*/activation_codes/plans/subscriptions/stripe_events/alerts/deliveries/follows/collections/smart_collections/blog_posts 等。
- Alembic 17 个迁移，head=0017；文件名与 revision 编号不一致（0002 文件 revision="0005"）。
- **`users`/`collections`/`collection_whales` 不在 Alembic**（Prisma 管）；Python 侧大量 `to_regclass` 防御探测 + 降级。
- `blog_posts` DDL 在 3 处重复（trade_ingest/api.py、worker.py、unified/app.py）+ blog_generator 自迁移加列。
- 双评分表：`whale_scores.final_score` 与 `whale_stats.whale_score` 并存。

## 5. 支付（services/payment）

- Checkout：mock 模式直接激活（原子 UPDATE 消除激活码 TOCTOU）；stripe 模式 create_checkout_session。
- Webhook：`stripe_events` 幂等；处理 completed 与 deleted/canceled。**不处理 invoice.payment_failed / subscription.updated / invoice.paid 续费事件**。
- 状态机 active/trialing/canceled/expired；每小时 expire 循环，仅无剩余 active 订阅时降级 FREE。

## 6. telegram_bot

- 激活码：8 位 A-Z0-9 写入 activation_codes；深链 `/start subscribe_pro|subscribe_elite`；按钮带 `{landing}/subscribe?plan=X&code=Y`。
- fan-out：按 (wallet, size_bucket, score_bucket) 缓存订阅者 → 来源分 whale_follow/collection/smart_collection/global/admin/health → 去重 + 按最高 plan 分组 → `deliveries` 表 (telegram_id, whale_trade_id) 唯一幂等。
- 限流：50/分钟（INCR+EXPIRE）；每日限额 Lua 原子；free=3/day。
- 命令：start/status/analyze/predict。

## 8. 已知问题

1. 生产路径残留大量 DEBUG 级 f-string 日志。
2. 凭证泄漏风险：redis_url（可能含密码）INFO 打印；bot token 拼进 URL。
3. SQL f-string：blog 查询（占位符安全但异味）、`/vw/metrics` ORDER BY 白名单拼接。
4. 硬编码 URL：gamma/clob/data-api/ensideas 等散落。
5. 双评分表并存。
6. 行为置信度混入质量分（`score = max(score, score_hint)`）。
7. `usd_thresholds.get("high", 400)` 默认值疑似笔误。
8. **健康检查向生产注入假交易**（health-market，钱包 0xabc…，amount 40000）——污染数据与队列。
9. 残留小 TOCTOU 窗口（_can_alert_event）；投递 at-least-once。
10. InMemoryRedis 用字符串匹配模拟 Lua 脚本（只支持两种），脆弱。

## 9. 从第一性原理看最重要的 5 个结构性事实

1. **本质是"管道 + 阈值"系统，不是预测模型**：价值在低延迟事件链与 fan-out；评分是确定性规则，无训练、无校准反馈环。
2. **评分 IP 只有一处真身**：`recompute_whale_stats` 的 5 因子公式；实时路径只是缓存分数 + 行为 hint 准入。
3. **架构已明显倒向单轨**（unified 单进程 + 内存队列）：代价是丢横向扩展与持久化，InMemoryRedis 只是勉强够用的替身。
4. **信任边界靠 DB 唯一约束**（on_conflict_do_nothing + 唯一索引），Redis 只当缓存/冷却/限流——设计一致，但 DB 承担全部竞争压力。
5. **存在未被迁移系统收编的影子 schema**：users/collections 归 Prisma，blog_posts DDL 三处重复，Python 侧靠 to_regclass 探测降级——单库、双迁移体系、运行时 DDL 叠加，是最脆弱的地方。
